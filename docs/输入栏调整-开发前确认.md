## 1.1.8.1 可行性复核（2026-10-26）

- `FFXIVClientStructs` 提供 `AddonChatLogPanel`，对应 `ChatLogPanel_0` 至 `ChatLogPanel_3`，有 `SetScale(float, bool)`；该入口缩放整个聊天面板，包含聊天记录、输入区域、背景和碰撞边界，不能证明只缩放聊天输入框。
- `AddonChatLogPanel` 暴露的 `ChatComponent` 是通用 `AtkComponentBase*`，没有公开的输入框专用子节点或稳定尺寸/布局 API；直接遍历/改写节点会依赖未确认的游戏版本节点编号。
- FFXIVClientStructs 的 addon 注册表未发现输入法候选栏 addon。Dalamud 文档只暴露内部 `DalamudIme` 的候选字符串/光标位置等状态，没有候选栏绘制缩放或跟随原生定位的公开接口。
- 因此 1.1.8.1 上无法同时满足“候选区域独立缩放”“聊天输入框独立缩放”“沿用原生定位与边界处理”“不影响输入逻辑”。
- 结论：不新增半成品源码，不修改清单，不推送测试仓库/测试库链；需要宿主或游戏 UI 提供稳定的子节点/IME 缩放接口，或明确接受整体聊天面板/自绘候选栏的需求变更后再继续。

## 新流程与本地重建版 0.2.0（2026-10-26）

- 用户确认 0.1.1、0.1.2 候选栏完全无变化，按未达成处理。
- 当前流程：开发 → 制作本地模块 → 测试仓库暂存 → Omni 更新至 1.1.8.2 → 统一调试和验证 → 同步正式仓库 → 删除测试仓库及测试库链。本文本节替代此前流程及等待用户验证描述。
- 0.2.0 替换 DalamudIme 的 Draw 事件订阅，不使用 Harmony，不清空 associatedViewport，不从 Framework.Update 缓存状态。改为绘制当帧读取候选与实际 viewport。
- 服务解析改用 Dalamud.Service<T>.GetNullable，不依赖可选的 MCP ServiceResolver。无法解析时明确报错，避免静默无效。
- 设置页增加版本、入口状态、绘制帧数和候选栏预览。1.00 倍及无候选数据时保留原绘制；自绘异常时尝试回退，停用恢复原事件订阅。
- 本机只有 Omni 1.1.8.1，已用其程序集做编译检查，0 警告、0 错误；不代表 1.1.8.2 安装或运行验证通过。清单最低版本设为 1.1.8.2，当前版本只在测试仓库暂存。
- 统一验证应检查：预览 1/2/3 倍；真实输入时绘制帧数、候选计数与状态；翻页/选词/取消；停用恢复；聊天框优化开关；窗口化与屏幕边缘；非 ImGui 输入来源是否能提供候选数据。
- 若真实候选栏不属于 DalamudIme，本实现不会改变该候选栏；须根据运行诊断确认实际绘制来源，再决定宿主适配。
